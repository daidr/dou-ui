# 大量数据

图表可以绘制上百万个数据点，也可以持续追加实时数据。

## 百万个点

下面的图表有 100 万个点，可以缩放和拖动平移。

<DocDemo src="chart/large" />

一个像素宽的位置最多只能看出最先、最低、最高和最后四个点，所以图表在每个像素列只画这四个点。画出来和逐点绘制一样，绘制量只和图表宽度有关。

图表还会做这些处理：

- 数据读成连续的数字数组并缓存，之后的重绘不再读取原始数据。
- 数据不再变化后，在浏览器空闲时为折线建立分段的最低点和最高点，缩放和平移时整段跳过。散点图建立网格索引，悬停时只查找指针附近的点。
- 图表滚出屏幕后不再绘制，回到屏幕上时再画。

## 使用建议

- 把数据放在 `shallowRef` 里，或用 `markRaw` 标记，避免 Vue 为每一行创建响应式代理。
- 更新时替换整个数组（或整个列对象），不要原地修改。缓存按数据本身区分，原地修改的数据不会重新读取。
- `x`、`y` 用字段名而不是函数。模板里写的箭头函数每次渲染都是新的，无法命中缓存。

## 按列给数据

`data` 也可以是一个对象，每个字段是一列，各列一样长。数据本来就是按列来的（例如接口返回的数组、二进制格式）时，不必先拼成一行一行的对象。

```js
const data = shallowRef({
  time: new Float64Array([/* … */]),
  value: new Float64Array([/* … */]),
})
```

- 列是 `Float64Array` 等类型化数组时，图表直接复制整列，也不占用逐行对象的内存。
- `x`、`y` 是函数时，函数拿到的行是由各列拼成的对象。提示框、点击和框选给出的行也是这样的对象，同一行每次都是同一个对象。

## 实时数据

实时数据也是每次换成新数组：在上一个数组的末尾加上新的行，需要时从开头去掉旧的行。下面的图表每 100 毫秒加一个读数，保留最近的 1 万个。

<DocDemo src="chart/live" />

图表认出新数组是接着上一个数组的，只读取新加的行，其余数值直接沿用。沿用有以下条件：

- 已有的行对象没有被改过。要修改某一行时，请换成一个新的对象。
- `x`、`y` 是字段名。是函数时，行移动后序号会变，每次都会全部重新读取。
- 数据按行给。按列给的数据每次都会全部重新读取。

## 性能参考

下面是在一台普通笔记本的 Chromium 里测出的每帧工作时间，图表宽 1200 像素。不同设备上的数字会不一样，手机通常要慢几倍。

| 场景                              | 时间         |
| --------------------------------- | ------------ |
| 100 万个点，按列给数据，首次绘制  | 约 45ms      |
| 100 万个点，按行给数据，首次绘制  | 约 70ms      |
| 100 万个点，缩放 / 平移每帧       | 约 4ms / 2ms |
| 100 万个点，悬停（折线 / 散点）   | 约 1ms       |
| 保留 1 万个点的实时数据，每次更新 | 约 2ms       |
| 10 万个散点，重绘                 | 约 50ms      |

数据点超过 2000 个时，图表不播放动画，散点图把所有圆点合成一张图再画出。
