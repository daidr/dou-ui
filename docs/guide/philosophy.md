# 设计原则

> 本页说明 DouUI 在结构、行为和 API 上的约定，会随着组件的增加不断修订。
> 外观方面的规范见 [视觉语言](./visual-language)。

DouUI 是一个为个人项目编写的组件库，目标是长期使用顺手，而不是满足所有场景。下面这些原则是做取舍时的依据。

## 1. 样式与组件分离

组件只负责结构和行为，样式全部由主题提供，两者之间通过语义 Token 关联。

- 组件样式中不直接写颜色、圆角、阴影等具体数值，只引用 `--dou-*` 变量。
- 所有样式集中在 `@dou-ui/theme` 中，组件包本身不包含样式。
- 切换主题只需要替换一组 CSS 变量，可以作用于整个页面，也可以只作用于某个区域。

调整视觉风格时只需要修改 Token，不需要改动组件。

## 2. Token 按用途命名

Token 名称表示用途，例如 `color.primary`、`color.bg.surface`、`radius.control`、`control.height.md`，
而不是 `blue-500` 这样的色板编号。组件只关心“主要操作用什么颜色”，不关心具体是哪种蓝色。

每种语气色只需要定义颜色本身和它上面的文字颜色，悬停、按下、浅色背景等状态由 `color-mix()` 计算得出。
修改一个颜色后，相关的状态色会一起更新。

## 3. Props 相互独立

Props 尽量设计成互不冲突的几个维度，而不是一串互斥的布尔值。

以按钮为例，`variant`（样式）、`tone`（语义）和 `size`（尺寸）可以任意组合，每种组合都有明确的效果。

所有组件使用同一套取值：

| 属性      | 取值                                                     |
| --------- | -------------------------------------------------------- |
| `size`    | `sm` / `md` / `lg`                                       |
| `tone`    | `neutral` / `primary` / `success` / `warning` / `danger` |
| `variant` | 由各组件定义，同名的变体在不同组件中含义相同             |

## 4. 只提供必要的 API

新增 prop 或插槽前，先确认确实有需要，不为假设的场景预留选项。

- 能用插槽实现的，不再加字符串 prop。例如图标通过插槽传入，而不是 `icon="xxx"`。
- 能用 CSS 变量调整的，不再加样式类的 prop。
- 默认值选择最安全的一项。例如按钮默认 `type="button"`，不会意外提交表单。

## 5. 内置无障碍支持

- 优先使用原生语义元素，按钮就渲染为 `<button>`。
- 状态能被读屏软件识别：加载中的按钮带 `aria-busy`，并且仍然可以聚焦。
- 焦点环只在键盘操作时显示（`:focus-visible`），动画遵循 `prefers-reduced-motion` 设置。

## 6. 样式容易覆盖

- 所有样式都放在级联层 `dou.tokens` → `dou.base` → `dou.components` 中。
  业务代码中不在级联层里的样式优先级总是更高，覆盖时不需要 `!important`，也不需要提高选择器权重。
- 类名遵循 `dou-块__元素--修饰` 的格式，运行时状态统一使用 `is-*`。
- 组件提供自己的局部变量（如 `--dou-button-height`），微调时修改变量即可。

## 7. 不影响页面的其他样式

引入 DouUI 不会重置或修改页面原有的样式。背景色、字体等主题样式只作用于声明了 `data-dou-theme` 的元素。

## 8. 完整的类型定义

Props、事件和插槽都有 TypeScript 类型声明并对外导出。导出的类型属于公开 API，修改时与组件本身同样对待。

## 9. 简单的工具链

- 运行时和包管理统一使用 Bun，格式化、脚本、CSS 打包等优先使用 Bun 的内置功能。
- 只有 Bun 暂不支持的部分（单文件组件编译、组件测试、lint）才引入其他工具。
- 构建产物保留模块结构，支持按需引入。

## 10. 表单控件基于原生元素

输入框、多选框、单选框都基于原生 `<input>`，DouUI 只负责样式和少量增强：

- 原生元素始终保留在原位（多选框、单选框只是在视觉上隐藏），点击、键盘、表单提交和自动填充都由浏览器处理。
- 未声明为 prop 的属性和事件会传递给原生元素，`placeholder`、`autocomplete`、`maxlength` 等属性不需要逐个封装；`class` 与 `style` 留在最外层的外框上，方便调整宽度与间距。
- 双向绑定统一使用 `v-model`；`CheckboxGroup`、`RadioGroup` 只负责把值和共享设置分发给每一项。

## 11. 属性有确定的落点

`class`、`style` 和其他未声明的属性（`id`、`aria-*`、`data-*`、事件监听）总有一个确定的落点，不会因为组件内部有多个根节点而丢失：

| 组件类型                                                                                 | `class` / `style` | 其他属性   |
| ---------------------------------------------------------------------------------------- | ----------------- | ---------- |
| 一般组件                                                                                 | 最外层元素        | 最外层元素 |
| 表单控件（输入框、自动补全、标签输入、验证码、数字输入、多行输入、多选框、单选框、开关） | 外框              | 原生控件   |
| 带弹出层的输入（Select、DatePicker、TimePicker、Cascader、ColorPicker）                  | 输入框外框        | 输入框外框 |
| 浮层（Tooltip、Popover、Dropdown、Popconfirm、ContextMenu、Dialog、Drawer）              | 浮层面板          | 浮层面板   |

所有导出的组件都有测试检查这条约定，新增组件会自动纳入。

## 12. 图标单独成包

`dou-ui` 不内置图标，图标通过插槽传入，`DouIcon` 只负责尺寸、颜色和无障碍语义。
配套的图标在独立的子包 [@dou-ui/icons](/icons/) 中，按需引入，不会把用不到的图标打包进来。
