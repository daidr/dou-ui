# 设计哲学

> 这份文档描述 DouUI 想成为什么样的组件库，会随着组件的增加不断修订。
> 这里只谈结构、行为与约定；"长什么样"见 [视觉语言](./visual-language)。

DouUI 首先是一个**为自己写的**组件库：它服务于真实的个人项目，追求的是长期用起来顺手，
而不是覆盖所有人的所有需求。下面这些原则是做取舍时的依据。

## 1. 外观是可替换的一层

组件负责**结构与行为**，主题负责**外观**，两者之间只通过语义 Token 对话。

- 组件的样式规则里不出现任何字面量颜色、圆角、阴影，只引用 `--dou-*` 变量。
- 所有样式集中在 `@dou-ui/theme`，组件包本身不携带样式。
- 换主题等于换一组 CSS 变量，可以全局换，也可以只换某个子树。

这样，风格可以随时演进：调整视觉语言只需要改 Token，组件不需要重写。

## 2. Token 描述角色，而非色板

Token 命名的是用途：`color.primary`、`color.bg.surface`、`radius.control`、`control.height.md`。
不暴露 `blue-500` 这样的色板位置，因为组件不应该知道"蓝色"，只应该知道"主要操作"。

每个语气只需定义颜色本身与其上的前景色，悬停、按下、浅底等状态由 `color-mix()` 推导。
**少定义，多推导**：一个颜色变化，整套状态自动跟上。

## 3. 正交的 API

Props 尽量做成彼此独立的维度，而不是一长串互斥的布尔值。

以按钮为例：`variant`（视觉权重）× `tone`（语义）× `size`（尺寸）。
任意组合都有定义，不存在"这个 type 和那个 plain 不能一起用"的情况。

整个库共享同一套词汇：

| 维度      | 取值                                                     |
| --------- | -------------------------------------------------------- |
| `size`    | `sm` / `md` / `lg`                                       |
| `tone`    | `neutral` / `primary` / `success` / `warning` / `danger` |
| `variant` | 按组件定义，但同名变体在不同组件中含义一致               |

## 4. 少即是多

每个 prop、每个插槽都需要一个存在的理由。宁可少一个开关，也不要多一个"以防万一"。

- 能用插槽表达的，不加字符串 prop（图标通过插槽传入，而不是 `icon="xxx"`）。
- 能用 CSS 变量调整的，不加样式类 prop。
- 默认值选最安全的那个：按钮默认 `type="button"`，永远不会意外提交表单。

## 5. 默认可访问

可访问性是组件的一部分，不是可选的增强。

- 优先使用原生语义元素（`<button>` 就是 `<button>`）。
- 状态要被读屏软件感知：加载中的按钮带 `aria-busy`，且仍可聚焦，焦点不会凭空消失。
- 只在键盘操作时显示焦点环（`:focus-visible`），并尊重 `prefers-reduced-motion`。

## 6. 可预测的覆盖

使用者一定会想改样式，DouUI 让这件事变得无聊：

- 所有样式都在级联层 `dou.tokens` → `dou.base` → `dou.components` 中，
  业务代码里任何不在 layer 中的规则都天然优先，不需要 `!important`，也不需要堆选择器。
- 类名遵循 `dou-块__元素--修饰`，运行时状态统一用 `is-*`。
- 组件暴露自己的局部变量（如 `--dou-button-height`），微调时改变量而不是改规则。

## 7. 不打扰宿主页面

引入 DouUI 不会重置、修改宿主页面的任何样式。主题的背景色、字体等只作用于显式声明了
`data-dou-theme` 的元素。

## 8. 类型即文档

Props、事件、插槽都由 TypeScript 类型声明并导出，编辑器的提示就是第一手文档。
导出的类型是公开 API 的一部分，和组件本身一样认真对待。

## 9. 工具链保持简单

- 运行时与包管理统一用 Bun，能用 Bun 内置能力（格式化、脚本、CSS 打包）的就不引入额外工具。
- 只有 Bun 暂时做不到的部分（单文件组件编译、组件测试、lint）才引入专门工具。
- 产物保持模块结构，天然支持按需引入。

## 10. 表单控件包住原生元素

输入框、多选框、单选框都以原生 `<input>` 为核心，DouUI 只负责外观与少量增强：

- 原生元素始终在原位（多选框、单选框只是视觉上隐藏），点击、键盘、表单提交、自动填充都是浏览器自己的行为。
- 没有声明为 prop 的属性和事件透传给原生元素，`placeholder`、`autocomplete`、`maxlength` 不需要逐个包装；`class` 与 `style` 则留在最外层的外框上，方便调整宽度与间距。
- 双向绑定统一使用 `v-model`；组（`CheckboxGroup`、`RadioGroup`）只负责把值和共享设置分发给每一项。

## 11. 属性落在一个确定的位置

`class`、`style` 和其他未声明的属性（`id`、`aria-*`、`data-*`、事件监听）总有一个确定的去处，不会因为组件内部有多个根节点而丢失：

| 组件类型                                                     | `class` / `style` | 其他属性   |
| ------------------------------------------------------------ | ----------------- | ---------- |
| 一般组件                                                     | 最外层元素        | 最外层元素 |
| 表单控件（输入框、数字输入、多行输入、多选框、单选框、开关） | 外框              | 原生控件   |
| 带弹出层的输入（Select、DatePicker）                         | 输入框外框        | 输入框外框 |
| 浮层（Tooltip、Popover、Dropdown、Dialog、Drawer）           | 浮层面板          | 浮层面板   |

所有组件都有测试覆盖这条约定。

## 12. 图标只提供容器

DouUI 不内置图标集。图标通过插槽传入，`DouIcon` 只负责尺寸、颜色跟随文字与读屏语义。
这样不绑定任何图标库，也不会把用不到的图形打进包里。
