# 版本与更新

DouUI 的所有包使用同一个版本号，一起发布。同一个应用里请让它们的版本保持一致，例如 `dou-ui` 与 `@dou-ui/sheet` 都用 `0.2.0`。

## 版本通道

每个版本都属于下面三个通道之一，通道由版本号的后缀决定，也是 npm 上的标签名。

- **正式版**，如 `0.2.0`，适合日常使用：

  ```sh
  bun add dou-ui
  ```

- **测试版**，如 `0.3.0-beta.1`，接口基本确定，之后通常只修问题，适合提前试用、反馈问题：

  ```sh
  bun add dou-ui@beta
  ```

- **预览版**，如 `0.3.0-alpha.0`，用来尝鲜，接口还可能变化：

  ```sh
  bun add dou-ui@alpha
  ```

同一个版本按预览版、测试版、正式版的顺序推进。正式版发布后，`alpha` 和 `beta` 标签如果还指向更旧的版本，会一并指到这个正式版。某个通道还没有发过版本时，对应的标签不存在，安装会报错，请换用另一个通道。

::: tip 首个正式版之前
npm 要求每个包都有 `latest` 标签。在 `0.1.0` 正式发布之前，`latest` 指向最新的预发布版本，`bun add dou-ui` 装到的就是它。
:::

## 版本号的含义

版本号遵循语义化版本。`1.0.0` 之前：

- 次版本号（`0.2.0` → `0.3.0`）的变化可能包含不兼容的改动，更新日志里会在「不兼容」一节单独列出，并说明怎么迁移。
- 修订号（`0.2.0` → `0.2.1`）只包含修复和不影响用法的改进。

`bun add` 默认写入的 `^0.2.0` 在 `1.0.0` 之前只接收修订号更新，不会自动升到 `0.3.0`，保持默认即可。

## 升级

各包之间按精确版本互相依赖，例如 `@dou-ui/sheet@0.2.1` 依赖的是 `dou-ui@0.2.1`。只升级其中一个会出现依赖版本不符的警告，甚至装上两份 `dou-ui`，所以请把用到的包一起升到同一个版本：

```sh
bun add dou-ui@0.2.1 @dou-ui/icons@0.2.1 @dou-ui/sheet@0.2.1
```

## 文档

| 地址                                         | 内容                                       |

页面顶部的版本菜单可以在两者之间切换到同一页；开发版新增、正式版还没有的页面，会在正式版站点上说明并提供回到首页的链接。

## 更新日志

每个版本的改动列在 [GitHub Releases](https://github.com/daidr/dou-ui/releases) 和仓库的 [CHANGELOG.md](https://github.com/daidr/dou-ui/blob/main/CHANGELOG.md)。正式版的一节汇总了它所有预发布版本的改动，并附上这些预发布版本的链接，只看正式版就能知道全部变化。

## 来源可验证

所有包都由 GitHub Actions 从公开的源码构建并发布，附带 npm 的透明度证明（provenance）。在 npm 的包页面可以看到每个版本对应的提交和构建记录，也可以在项目里运行：

```sh
npm audit signatures
```
