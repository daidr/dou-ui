# 版本与更新

DouUI 的所有包使用同一个版本号，一起发布。同一个应用里请让它们的版本保持一致，例如 `dou-ui` 与 `@dou-ui/sheet` 都用 `0.2.0`。

## 版本通道

每个版本都属于下面三个通道之一，通道由版本号的后缀决定，也是 npm 上的标签名：

| 通道   | 版本号示例      | 安装                   | 适合               |
| ------ | --------------- | ---------------------- | ------------------ |
| 正式版 | `0.2.0`         | `bun add dou-ui`       | 日常使用           |
| 测试版 | `0.3.0-beta.1`  | `bun add dou-ui@beta`  | 提前试用、反馈问题 |
| 预览版 | `0.3.0-alpha.0` | `bun add dou-ui@alpha` | 尝鲜，接口仍会改   |

同一个版本按预览版、测试版、正式版的顺序推进。测试版的接口基本确定，之后通常只修问题；预览版的接口还可能变化。正式版发布后，`alpha` 和 `beta` 标签如果还指向更旧的版本，会一并指到这个正式版。

::: tip 首个正式版之前
npm 要求每个包都有 `latest` 标签。在 `0.1.0` 正式发布之前，`bun add dou-ui` 安装的是最新的预发布版本。
:::

## 版本号的含义

版本号遵循语义化版本。`1.0.0` 之前：

- 次版本号（`0.2.0` → `0.3.0`）的变化可能包含不兼容的改动，更新日志里会在「不兼容」一节单独列出，并说明怎么迁移。
- 修订号（`0.2.0` → `0.2.1`）只包含修复和不影响用法的改进。

所以在 `package.json` 里推荐用 `~0.2.0` 这样只接收修订号更新的写法。

## 文档

| 地址                                         | 内容                                       |
| -------------------------------------------- | ------------------------------------------ |
| [ui.daidr.me](https://ui.daidr.me)           | 当前正式版                                 |
| [next.ui.daidr.me](https://next.ui.daidr.me) | 开发版，跟随主分支，可能包含尚未发布的功能 |

页面顶部的版本菜单可以在两者之间切换到同一页。

## 更新日志

每个版本的改动列在 [GitHub Releases](https://github.com/daidr/dou-ui/releases) 和仓库的 [CHANGELOG.md](https://github.com/daidr/dou-ui/blob/main/CHANGELOG.md)。正式版的一节汇总了它所有预发布版本的改动，只看正式版就能知道全部变化。

## 来源可验证

所有包都由 GitHub Actions 从公开的源码构建并发布，附带 npm 的透明度证明（provenance）。在 npm 的包页面可以看到每个版本对应的提交和构建记录，也可以在项目里运行：

```sh
npm audit signatures
```
