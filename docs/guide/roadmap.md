# 路线图

> 记录 DouUI 打算做哪些组件、按什么顺序做，以及每一批要先解决的基础设施。随进度更新。

## 排序原则

1. **先原子，后组合**：先把按钮、输入框、选择控件这些"最小单位"做扎实，复杂组件由它们拼出来。
2. **先解决基础设施，再做依赖它的组件**：浮层定位、焦点管理、层级管理先于下拉框、对话框。
3. **每个组件一次做完**：实现、样式、测试、文档、playground 一起交付，不留"之后再补文档"。
4. **只做自己会用到的**：路线图上的组件是真实项目里会用到的，不追求数量。

## 横向事项

- **国际化**：组件内置的读屏文案（如"清空""移除"）目前为中文，第 2 批随 `ConfigProvider` 一起提供替换方式。
- **暗色模式核对**：每个组件都在亮 / 暗两套主题下截图确认。
- **可访问性**：每个组件写明键盘与读屏行为，并在测试中覆盖关键的 ARIA 属性。
