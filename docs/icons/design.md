# 设计哲学与绘制规范

`dou-icons` 不是一套“够用就行”的符号，而是 DouUI 视觉语言在图形上的延伸：组件用 1px 的发丝线和层叠的柔和阴影表达质感，图标就用一支细而稳定的笔，在留白里把意思说清楚。

## 设计哲学

**轻。** 图标是文字的同伴，不是主角。线条细、留白多，放在正文、按钮和菜单里时不抢视线，也不显得单薄。

**圆。** 所有笔画圆头圆角，容器带着宽松的圆角，弧线多于折角。几何是骨架，圆润是性格：理性但不冷硬。

**静。** 只画“这是什么”，不画“它有多厉害”。不加速度线、高光、阴影和透视；一个图标最多一处点睛的细节，而且这处细节必须承载含义。

**一致。** 一个 16px 的图标和一个 48px 的图标，看起来应该是同一种分量；圆、方、长条形状放在一行里，看起来应该一样大。

## 视觉语言

### 网格

- 画布 `24 × 24`，主体落在 `3 ~ 21` 之间，四周留出约 3 格的呼吸空间。
- 坐标取 `0.25` 的整数倍；能落在整格或半格的，尽量落在整格或半格。

### 线

- 线宽做**光学补偿**：随尺寸变化，但比图形本身变化得慢。按比例缩放会让小图标糊、大图标笨重；完全固定又会让小图标显粗、大图标显虚。dou-icons 取两者之间：

  | 图标尺寸 | 16px   | 20px   | 24px  | 32px   | 48px   |
  | -------- | ------ | ------ | ----- | ------ | ------ |
  | 线宽     | 1.25px | 1.38px | 1.5px | 1.75px | 2.25px |

  公式为 `0.75px + 尺寸 / 32`，24px 时正好是 1.5px，也就是源文件里写的线宽。

- 圆头（`round` cap）、圆角（`round` join），线的端点永远是圆的。
- 平行的笔画中心距至少 **4 格**。这样图标在 16px 下也能保持透气，不会挤成色块。

### 点

- 点是图标里唯一的“实心”，用于 i、!、? 的点，锁孔，列表符号，更多（⋯）等。
- 点比线略重（线宽的 1.5 倍），这样它读起来是“点”，而不是一截没画完的线。

### 断开

断开是 dou-icons 的点睛手法，但只用在“断开本身有含义”的地方，过犹不及：

- **主体轮廓保持闭合。** 文件、盒子、云、气泡这类外形是图标的骨架，不为了风格去打断。
- **每个图标最多一处断开。**
- 只在三种场合断开，而且只用在简单的元素上；锁、日历这类整体性强的图形保持完整：
  - **前后遮挡**：被挡住的那条线在交叠处断开，不画交叉线，例如 `copy`。
  - **可分离的部件**：本来就能分开的部分之间留缝，例如 `sliders` 的滑钮与轨道。
  - **悬浮的内部元素**：框里的分隔线、折线变成不碰边框的圆头短条，例如 `sidebar`、`mail`、`ban`。
- 缝隙统一：断开处线端与相邻笔画中心的距离为 3 格，视觉上约留出一条线宽的空隙。

### 圆角

- 容器类外形（卡片、屏幕、文件、日历等）的圆角为 **3 格**；较小的部件用 1.5 ~ 2 格。
- 不出现尖锐的直角转折；需要折角的地方由圆角连接自然处理。

### 视觉尺寸

不同外形在同样的数值尺寸下看起来大小不一，所以按外形对齐到各自的基准框，而不是都撑满画布：

| 外形     | 基准                       | 例子                        |
| -------- | -------------------------- | --------------------------- |
| 圆形     | 直径 18（`r = 9`）         | info、clock、globe          |
| 正方形   | 约 16 × 16                 | home、grid、stop、copy      |
| 横长方形 | 约 18 ~ 19 × 14 ~ 16       | mail、monitor、credit-card  |
| 竖长方形 | 约 15 × 18 ~ 19            | file、smartphone、bookmark  |
| 线性符号 | 长 14（`5 ~ 19`）          | 箭头、plus、menu            |
| 特殊外形 | 允许略微越过基准，视觉为准 | star、heart、alert-triangle |

同一家族共用外形，只换内部符号：`info` / `alert-circle` / `check-circle` / `x-circle` 是同一个圆，箭头类共用同一种箭头头部的角度和长度。

### 颜色

只有一种颜色：`currentColor`。不填充面，不使用透明度和渐变；图标的颜色永远跟随文字。

## 文件结构

每个图标由同名的两个文件组成，放在 `packages/icons/icons/`：

```
icons/
  search.json         元信息
  search.stroke.svg   线性变体
```

`search.json` 描述元信息：

```json
{
  "label": "搜索",
  "categories": ["actions"]
}
```

`search.stroke.svg` 是可以直接预览的完整 SVG，根元素的属性固定，内部只放 `path`、`circle`、`ellipse`、`rect`、`line`、`polyline`、`polygon`，且只写几何属性；点写成 `<path class="dot" d="Mx yh.01" />`，品牌图标里需要保留粗细变化的笔画可以加 `class="fill"` 画成填充形状：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round">
  <circle cx="12" cy="12" r="9" />
  <path d="M12 11v5.5" />
  <path class="dot" d="M12 7.75h.01" />
</svg>
```

`bun run gen` 会校验所有文件（根属性、允许的元素与属性、点的写法、标签与分类），再为每个图标生成一个组件模块、导出入口与元信息。校验不通过时会列出具体文件与原因。

## 品牌图标

`brands` 分类收录常见公司、软件与框架的标志。它们不是照搬原标志，而是用同一套规则重画的线性版本：

- **保留辨识特征，舍弃细节。** 只留下认出它所必需的结构，比如 Vue 的双层 V、React 的三条轨道、微信的两个气泡；渐变、多色与填充一律去掉，只用 `currentColor` 的线条表达。
- **规则照旧。** 同样的 24 网格、光学线宽、圆头圆角和视觉尺寸；原本是实心块面的部分改为轮廓。
- **粗细本身是特征时才保留。** 少数标志靠笔画的粗细变化被认出来，比如支付宝向右逐渐变粗的一撇、Claude 末端更宽的光芒、YouTube 实心的播放键。这些部分画成填充形状（`class="fill"`），外沿仍有同样的线条包住，所以端点和转角依旧是圆的。品牌之外的图标不使用填充。
- **遮挡才断开。** 原标志里互相交叠的部分（X 的两笔、微信的两个气泡、OpenAI 的六个环）用“断开”表现前后关系，不额外制造断口。

品牌标志的商标权归各自所有者，使用时请遵守对应品牌的使用规范。

## 变体

目前只提供线性变体（`stroke`）。后续增加其他变体时，同一个图标会多一个 `<name>.<variant>.svg` 文件，组件名带上变体后缀，元信息里的 `variant` 区分它们；现有的线性图标名称保持不变。
