# 设计规范

本页说明 `@dou-ui/icons` 的设计原则和绘制规则。图标与 DouUI 组件使用同一套视觉语言：细线条、圆角、留白充足。

## 设计原则

**轻。** 图标通常与文字搭配使用，线条细、留白多，放在正文、按钮和菜单中时不会过于醒目，也不会显得单薄。

**圆。** 所有笔画使用圆头和圆角连接，外框带较大的圆角，尽量用弧线代替尖角。

**静。** 只表达图标的含义，不加速度线、高光、阴影和透视等装饰。一个图标最多保留一处细节，并且这处细节必须有含义。

**一致。** 16px 和 48px 的图标视觉粗细应当一致；圆形、方形、长条形的图标放在一行时，视觉大小应当相同。

## 视觉语言

### 网格

- 画布 `24 × 24`，主体落在 `3 ~ 21` 之间，四周留出约 3 格的空白。
- 坐标取 `0.25` 的整数倍；能落在整格或半格的，尽量落在整格或半格。由圆弧切点算出来的坐标（如 `2.12`）可以例外。
- 新画的图标，横线、竖线和容器边优先放在**半格**（`x.5`）上：线宽 1.5 时，半格上的线在 24px 普通屏上是一排实像素，整格上的线会变成两排灰。容器宽高取奇数（15、17），两边就都在半格上，并且仍然居中。图标在 13 ~ 16px 时网格与像素对不上，这条只对 24px 起作用，所以不追改旧图标。
- 斜线优先 45°，其次 30°、60°。

### 线

- 线宽做**光学补偿**：随尺寸变化，但比图形本身变化得慢。按比例缩放会让小图标糊、大图标笨重；完全固定又会让小图标显粗、大图标显虚。@dou-ui/icons 取两者之间：

  | 图标尺寸 | 16px   | 20px   | 24px  | 32px   | 48px   |
  | -------- | ------ | ------ | ----- | ------ | ------ |
  | 线宽     | 1.25px | 1.38px | 1.5px | 1.75px | 2.25px |

  公式为 `0.75px + 尺寸 / 32`，24px 时正好是 1.5px，也就是源文件里写的线宽。

- 圆头（`round` cap）、圆角（`round` join），线的端点始终是圆的。
- 平行的笔画中心距至少 **4 格**。这样图标在 16px 下也能保持透气，不会挤成色块。

### 点与实形

基础图元只有三种：线、点、实形。

- **点**用于 i、!、? 的点，锁孔，列表符号，更多（⋯）等标点性质的小记号。点比线略重（线宽的 1.5 倍），这样它读起来是“点”，而不是一截没画完的线。
- **实形**是填满的面，外加一圈线宽的描边，所以边角和线条一样是圆的。实形只有下面三种用法：
  - **实心四角星**：专用于 AI 场景（`sparkles`、`search-sparkle`、`message-sparkle`、`text-sparkle`），表示“由 AI 生成或参与”。四角星不用于其他含义，魔法棒、收藏这类场景用五角星。
  - **实心圆点**：当点本身就是图形的主体，而不是标点时，用实心圆点代替点。半径 1.25（连描边直径 4），用于 `square-dot`、`arrow-up-from-dot`、`arrow-down-to-dot`；作为提醒角标时半径 1.5（连描边直径 4.5），用于 `bell-dot`。再小的圆点在 16px 下几乎看不见。
  - **部分填充**：表示“一半”这类程度，只填满轮廓的一部分，轮廓本身照常描边，例如 `star-half`。
- 除此之外不填充面。

源文件写法：

```html
<path class="dot" d="M12 8h.01" />
<path
  class="fill"
  d="M12 7.25Q12.6 10.4 15.75 11Q12.6 11.6 12 14.75Q11.4 11.6 8.25 11Q11.4 10.4 12 7.25Z"
/>
<path class="fill" d="M10.75 12a1.25 1.25 0 1 0 2.5 0a1.25 1.25 0 1 0-2.5 0" />
```

### 断开

断开是 @dou-ui/icons 的点睛手法，但只用在“断开本身有含义”的地方，过犹不及：

- **主体轮廓保持闭合。** 文件、盒子、云、气泡这类外形是图标的骨架，不为了风格去打断。
- **每个图标最多一处断开。**
- 只在三种场合断开，而且只用在简单的元素上；锁、日历这类整体性强的图形保持完整：
  - **前后遮挡**：被挡住的那条线在交叠处断开，不画交叉线，例如 `copy`。
  - **可分离的部件**：本来就能分开的部分之间留缝，例如 `sliders` 的滑钮与轨道。
  - **悬浮的内部元素**：框里的分隔线、折线变成不碰边框的圆头短条，例如 `sidebar`、`mail`、`ban`。
- 缝隙统一：断开处线端与相邻笔画中心的距离为 3.5 格，16px 下约留出 1px 的空隙。

### 关闭（off）

- 斜线是 45° 的完整长线，从左上贯穿到右下（`phone-off` 因听筒本身沿主对角线，改用反向对角线）；`ban` 的斜线在圆内，是例外。
- 只在一侧留缝：斜线左下一侧的图形直接接到斜线上，右上一侧留 3.5 格的缝，看起来像斜线压在图形上。
- 切开后长度不足 3 格的碎段、拐角后不足 1.5 格的小钩一律删掉；会和斜线贴着平行走的部件（例如闹钟右脚）直接省略。

### 复数（堆叠）

带 s 的复数图标（`files`、`images`、`messages`、`bookmarks`）统一画成两层：前景完整，放在右上；背景是同形的物体，只露出左边和底边，两端停在圆角的中点，不在直边上生硬截断。重心落在下方，不会头重脚轻。

### 小尺寸

图标最常用的尺寸是 13 ~ 16px。24 网格的 1 格在 16px 下只有 0.67px，线宽 1.25px，所以：

- **最小间隙**：不相连的两笔，中心距至少 **3.5 格**。两条中心线相距 d 格时，16px 下的白缝是 `d × 0.667 − 1.25` px：3.5 格约 1px，低于 2.5 格就看不出缝，两笔粘成一团。
- **锐角**：两笔以小于 40° 的夹角相交时，夹缝在小尺寸下会被填满。交点附近同样要满足 3.5 格的间隙；做不到就开大角度，或者在交点处断开。
- **接点要准**：要连上的两笔，端点必须落在对方的中心线上；差 0.2 格也算没对准。要么连上，要么留足 3.5 格，不要介于两者之间。
- **16px 能认出来**：每个图标都要在 16px、1 倍屏的像素图里确认细节分得开（评审图里的“16px · 1×”）。高清屏上的预览看不出这个问题。
- **角标只用简单符号**：5 × 5 的角标格子在 16px 下只有 3px 多，只放加、减、叉、勾、点、四角星、箭头。齿轮、放大镜、锁、时钟、爱心、星星这类复杂符号，要么放大角标并让出主体，要么不做这个变体。

### 角标与内部符号

同一种修饰符号在同一族里只有一种画法，换的只是符号本身：

- **角标**放在主体外的角上，用 `5 × 5` 的格子：加号臂长 5，叉号 4，减号 5，勾号 `1.75 1.75 3.25-3.25`，四角星半径 3。右下角的格子中心在 `(18, 18)`，右上角在 `(18, 6)`，人物类在头部右侧 `(18.5, 10.5)`，时钟类缩小表盘后放在 `(17.5, 17.5)`；主体被角标挡住的地方按距格子中心 5.5 截断（4.5 时 16px 下角标会和主体粘在一起）。
- **列表类**（`list-plus`、`list-x`、`list-music` 等）共用同一组三行：`y = 6.5 / 12 / 17.5`，从 `x = 4` 起，长度依次 16、9、7；角标与第三行对齐，格子中心在 `(18, 17.5)`。
- **内部符号**画在容器里，大小跟随容器：小容器（文件夹、日历、盾牌）用加号 5、叉号 4、勾号 `1.75 1.75 3.25-3.25`；大一些的容器（文件、剪贴板、消息、副本）用加号 6、叉号 4.5、勾号 `2 2 4-4`。
- 音符、播放等组合符号沿用独立图标的画法，例如音符的符尾都向右下。
- **复杂符号**用简化画法，保证 16px 下还能分开：
  - **齿轮**：半径 2.5 的圆环加 6 根长 1.5 的短齿（从圆环向外到半径 4，正上方一根），不画齿形轮廓和中心孔。`settings` 这类以齿轮为主体的图标仍用完整齿轮。
  - **表盘**：半径 4，指针向上 1.5、再向右下 `1.25 .75`，方向与 `clock` 一致。
  - 作角标时，表盘的主体按距符号中心 6.5 截断，与符号留出 2.5 的间隙；齿轮的齿向四周发散，主体按 7 截断，留出 3。
  - **放大镜**作角标时，镜片半径 3、中心一般在 `(16.5, 16.5)`，手柄沿 45° 伸到 `(20.5, 20.5)`；主体按距镜片中心 6 截断，与镜片留出 3。留得再多，主体被截掉的部分太长，日历右侧这类短边会整段消失。
  - 星星、爱心随容器调整大小，与容器边至少留 2.5。

### 圆角

- 容器类外形（卡片、屏幕、文件、日历等）的圆角为 **3 格**；中等的外形（铃铛、书签、书本等）用 2.5 格；较小的部件用 1.5 ~ 2 格。
- 不出现尖锐的直角转折；需要折角的地方由圆角连接自然处理。

### 视觉尺寸

不同外形在同样的数值尺寸下看起来大小不一，所以按外形对齐到各自的基准框，而不是都撑满画布：

| 外形     | 基准                       | 例子                        |
| -------- | -------------------------- | --------------------------- |
| 圆形     | 直径 18（`r = 9`）         | info、clock、globe          |
| 正方形   | 约 16 × 16                 | home、grid、stop、copy      |
| 横长方形 | 约 18 ~ 19 × 14 ~ 16       | mail、monitor、credit-card  |
| 竖长方形 | 约 15 × 18 ~ 19            | file、smartphone、bookmark  |
| 线性符号 | 长 14（`5 ~ 19`）          | 箭头、plus、menu            |
| 特殊外形 | 允许略微越过基准，视觉为准 | star、heart、alert-triangle |

线条多、内部格子多的图标会显得更黑。评审工具会算出每个图标的墨量（24px 下覆盖的面积）与全库中位数的比值，超过 1.45 倍的要减线或放大留白，确实需要的写明理由。

同一家族共用外形，只换内部符号：`info` / `alert-circle` / `check-circle` / `x-circle` 是同一个圆，箭头类共用同一种箭头头部的角度和长度。

### 颜色

只有一种颜色：`currentColor`。除了上文列出的实形，不填充面；不使用透明度和渐变；图标的颜色始终跟随文字。

## 评审

新增或修改图标后，逐个生成评审图再提交：

```sh
cd packages/icons
bun run review search,filter        # 指定图标
bun run review --category layout    # 一个分类
bun run review --all --out review   # 全部
```

每个图标会放大画在 24 网格上，叠加关键线、`3 ~ 21` 安全区和笔画中心线，下面是 16 / 20 / 24 / 32 / 48 五档实际渲染，以及 16px 在 1 倍屏上的像素放大图。装有 Playwright 时还会截图并自动测量：

- **包围盒**：越过 `3 ~ 21` 的会提示（横长、竖长和特殊外形可以到 `2.5 ~ 21.5`），超出 `2.5 ~ 21.5` 的一定要改。
- **间隙**：不相连的两笔中心距小于 3.5 格的位置会画上圈。红圈小于 2.5 格，16px 下一定粘连；橙圈在 2.5 ~ 3.5 格之间，偏紧。小于 1.2 格的通常是接点没对准或夹角太尖。
- **墨量**：与全库中位数的比值，超过 1.45 倍的提示偏重。

红圈必须改；橙圈在角标和容器里的小符号上可以接受（空间有限），其余情况尽量改到 3.5。人物类头和身体之间的 2.25 是既定画法，不算问题。自动检测是近似的，提示要逐条看图确认。逐个检查：外形是否贴合基准框、平行笔画间距是否够 4 格、断开是否合规、间隙是否够 3.5 格、16px 像素图里细节是否分得开、同族图标是否共用骨架。

**同族回溯**：新增或修改一个图标时，把它和同族的全部现有图标排在一起对比，不只看它自己。同族指名称前缀相同（`list-*`、`user-*`、`clock-*`）或画法相同（带角标、带内部符号）的图标。逐项核对：骨架的位置和尺寸、行距与线长、角标或内部符号的位置和大小、勾号与叉号的比例、点和实形的用法。有一处不一致，就以族里多数的画法为准统一，必要时一起改掉旧图标。

## 文件结构

每个图标由同名的两个文件组成，放在 `packages/icons/icons/`：

```
icons/
  search.json         元信息
  search.stroke.svg   线性变体
```

`search.json` 描述元信息：

```json
{
  "label": "搜索",
  "categories": ["actions"]
}
```

`search.stroke.svg` 是可以直接预览的完整 SVG，根元素的属性固定，内部只放 `path`、`circle`、`ellipse`、`rect`、`line`、`polyline`、`polygon`，且只写几何属性；点写成 `<path class="dot" d="Mx yh.01" />`：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round">
  <circle cx="12" cy="12" r="9" />
  <path d="M12 11v5.5" />
  <path class="dot" d="M12 7.75h.01" />
</svg>
```

`bun run gen` 会校验所有文件（根属性、允许的元素与属性、点的写法、标签与分类），再为每个图标生成一个组件模块、导出入口与元信息。校验不通过时会列出具体文件与原因。

## 变体

目前只提供线性变体（`stroke`）。后续增加其他变体时，同一个图标会多一个 `<name>.<variant>.svg` 文件，组件名带上变体后缀，元信息里的 `variant` 区分它们；现有的线性图标名称保持不变。
